## 개요
 
함께 아이온을 하던 지인이 블로그로 경제적 자유를 누리고 있었다. 자동화 파이프라인에 한창 빠져 있던 시기였고, 블로그 수익화는 예전부터 해보고 싶었던 일이었는데 그 모습을 보고 구체적인 동기가 생겼다.<br>
비슷한 시기에 유튜브에 "AI Agent"라는 개념이 올라오기 시작했다. 클로드를 써보고 바로 결제했다. 직접 방문한 맛집 경험을 텔레그램으로 인터뷰하듯 대화하면, Claude API가 패션 잡지 스타일의 한국어 아티클로 정리하고, 검토·컨펌을 거쳐 영어·일본어로 번역해 노션에 발행하는 에이전트를 만들기로 했다.
<br>
 
## 접근 방식
 
- **가장 귀찮은 일부터 자동화 대상으로 잡았다** <br>
    블로그 운영에서 제일 힘든 건 글을 쓰는 일 자체였다. 인터뷰하듯 대화만 하면 아티클이 완성되는 구조를 목표로 삼았다.<br>
- **타겟 언어를 한국어가 아니라 영어·일본어로 잡았다** <br>
    애드센스 수익은 원화보다 외화가, 한국어보다 이용자 수가 많은 언어가 유리하다는 판단으로, 한국어 원고를 컨펌받은 뒤 영어·일본어로 번역해 발행하는 구조로 설계했다.<br>
- **설계 문서를 먼저 쓰고, 구현 단계에서 단순화했다** <br>
    처음에는 인터뷰 에이전트·초안 에이전트·발행 에이전트로 나누는 멀티 서브에이전트 구조로 설계했다. 이 프롬프트 구조는 유튜브에서 참고한 것이었는데, 막상 내가 가장 원했던 기능은 어디서든 짬이 날 때 대화만으로 포스팅이 되는 것이었다. 그래서 `bot.py` 텔레그램 봇으로 Claude API 호출, 번역, 노션 업로드까지 전부 처리하는 구조로 바꿨다.<br>
- **MVP 범위를 노션 발행까지로 한정했다** <br>
    워드프레스가 최종 목표였지만, 이후 확장 가능한 구조로만 설계해두고 1차 목표는 노션 발행으로 좁혀 테스트 기간을 거치기로 했다.<br>
<br>

## 기술 스택
- Claude API (Anthropic, `claude-sonnet-4-6`) — 인터뷰 진행, 아티클 생성, 수정 반영, 번역까지 전담
- python-telegram-bot — 텔레그램 봇 서버, 메시지·사진 핸들러
- notion-client (Notion 공식 SDK) — 페이지 생성, 마크다운→노션 블록 변환, Files API 사진 업로드
- Python (asyncio, dotenv) — 이때도 JS 때와 마찬가지로, 하루이틀 정도 생활코딩으로 파이썬을 먼저 공부했다.
<br>

## 기술적 도전과 해결
 **1: 토큰 낭비 최소화**
- 원인: 메시지가 올 때마다 "지금 뭘 하려는 요청인지"를 매번 Claude에게 판단시키면, 그 판단 자체에도 토큰이 든다. 게다가 인터뷰·초안·번역처럼 단계마다 필요한 규칙이 다른데, 이걸 하나의 시스템 프롬프트에 다 넣으면 매 호출마다 불필요한 텍스트까지 함께 보내야 했다.
- 해결: `/start`, `/draft`, `/publish`, `/status`, `/stop`, `/help` 같은 슬래시 커맨드를 스킬 단위로 만들어서, "지금 뭘 원하는지"를 AI가 추측하게 두지 않고 사람이 직접 명령으로 골라 부르게 했다. 커맨드가 호출되면 그때 필요한 스킬(예: 초안 단계엔 `article-generator`)만 시스템 프롬프트에 실었다.
- 결과: 요청을 해석하는 데 드는 토큰을 없애고, 실행 단계에 필요한 규칙만 그때그때 불러오면서 전체 호출 비용을 줄였다.<br>
**2: AI 글쓰기 톤 일관성**
- 원인: "패션 잡지 스타일"이라는 톤을 텍스트로 아무리 자세히 설명해도, 그 설명 자체가 프롬프트를 무겁게 만들고 결과물의 일관성도 보장하지 못한다.
- 해결: **설명 대신 과거에 실제로 발행했던 최근 3개 세션의 결과물을 `published_references/`에 저장해두고, 이걸 few-shot 예시로 프롬프트에 끼워 넣었다.**
- 결과: 긴 설명 없이도 실제 예시 몇 개만으로 톤을 일관되게 유지할 수 있었고, 발행할 때마다 최신 발행본으로 계속 갱신되는 구조를 만들었다.
<br>

## 코드 샘플
 <br>
`/help`, `/draft`, `/publish` 같은 슬래시 커맨드가 곧 스킬이다 — 필요한 기능만 호출해서 쓰도록 등록
<br>

    ```python
    def main() -> None:
        app = Application.builder().token(TELEGRAM_BOT_TOKEN).build()
        app.add_handler(CommandHandler("start",   on_start))
        app.add_handler(CommandHandler("draft",   cmd_draft))     # 한국어 초안 재생성
        app.add_handler(CommandHandler("publish", cmd_publish))   # 번역 + 정식 발행
        app.add_handler(CommandHandler("status",  cmd_status))    # 현재 세션 상태 확인
        app.add_handler(CommandHandler("stop",    cmd_stop))
        app.add_handler(CommandHandler("help",    cmd_help))
        app.add_handler(MessageHandler(filters.TEXT & ~filters.COMMAND, on_message))
    ```
<br>    
커맨드가 호출되면, Claude에게 "뭘 원하는지" 묻지 않고 바로 해당 기능만 실행한다<br>

```python
async def cmd_draft(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
    """한국어 초안 재생성 + 노션 업로드."""
    session = session_mgr.load()
    if not session.get("conversation_history"):
        await update.message.reply_text("인터뷰 기록이 없어요. 먼저 인터뷰를 진행해주세요.")
        return
    session_mgr.update({"stage": "drafting"})
    await run_draft(update, session_mgr.load())   # article-generator 스킬만 이때 로드됨
 
 
async def cmd_help(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
    await update.message.reply_text(
        "📖 사용 가능한 명령어\n\n"
        "/draft — 한국어 초안 재생성 + 노션 업로드\n"
        "/publish — 영어/일본어 번역 + 정식 발행\n"
        "/status — 현재 세션 상태 확인\n"
        "/help — 이 메시지 표시"
    )
```
 <br>

반대로, 명시적 커맨드가 없는 일반 대화(인터뷰 중)에서는 완료 여부를 Claude가 판단해야 한다<br>

```python
async def run_interview(update: Update, session: dict, text: str) -> None:
    history = session.setdefault("conversation_history", [])
    history.append({"role": "user", "content": text})
 
    raw = await _claude(_interview_system(session), history)
    parsed = _parse_json(raw)
    message, is_complete = parsed.get("message", raw), parsed.get("interview_complete", False)
 
    session["covered_topics"] = parsed.get("covered_topics", session.get("covered_topics", []))
    session_mgr.save(session)
    await update.message.reply_text(message)
 
    if is_complete:
        session["stage"] = "drafting"
        await run_draft(update, session)
```

```python
def convert(md_text: str) -> list[dict]:
    blocks = []
    lines = md_text.splitlines()
    i = 0
    while i < len(lines):
        line = lines[i]
        if line.startswith("# "):
            blocks.append(_heading(line[2:].strip(), 1))
        elif line.strip().startswith("|") and re.match(r"\|[-| :]+\|", lines[i + 1]):
            # 표 파싱
            ...
        elif line.startswith("Q.") or line.startswith("Q "):
            blocks.append(_paragraph(f"**{line.strip()}**"))
        elif line.startswith("A.") or line.startswith("A "):
            blocks.append(_paragraph(line.strip()))
        i += 1
    return [b for b in blocks if b is not None]
```

- 클로드 API로 만든 첫 챗봇이었고, 텔레그램 인터뷰 → 한국어 초안 → 검토·컨펌 → 영어/일본어 번역 → 노션 발행까지 이어지는 파이프라인의 테스트 버전을 완성했다.
- 파이프라인은 완성했지만, 실사용에서는 컴퓨터를 계속 켜놔야 봇이 살아있다는 현실적인 한계에 부딪혔다. 니즈에 반하는 비경제적 선택이었다.
- 대신 이 한계를 겪으면서 라즈베리파이 같은 상시 구동 장비의 존재를 처음 알게 됐고, "24시간 떠 있어야 하는 서비스는 결국 인프라 문제"라는 걸 체감했다. 다음에 비슷한 걸 만든다면 로컬 프로세스가 아니라 상시 구동 가능한 형태로 설계해야 한다는 감각이 생겼다.
