### 개요
 
창업경진대회를 준비하며 팀회의가 길어졌는데 녹음을 다시 들으며 회의록을 손으로 정리하는 게 비효율적이었다. 마침 친한 개발자분이 로컬 LLM으로 회의록을 만들면 신세계라고 했던 말이 생각나 실행해 보았다.
<br>

**회의 음성을 넣으면 (1) 정형화된 회의록과 (2) 발언자별 핵심 발언 요약, 두 가지 결과물이 동시에 나오는 파이프라인이다.**
<br>
<br>

### 접근 방식
 - **전사와 화자 구분은 로컬에서 처리했다** — WhisperX로 오디오를 텍스트화하면서 동시에 화자 분리(diarization)까지 수행해, "누가 무슨 말을 했는지"가 살아있는 전사본을 만들었다.
- **요약은 로컬 LLM으로, 목적에 따라 프롬프트를 분리했다** — 같은 전사본을 두 개의 서로 다른 프롬프트에 태워서, 회의록용(제목·일시·참석자·논의내용·결정사항·액션아이템 등 11개 항목)과 발언자별 요약용(화자별 주요 발언·결정·제안)을 각각 뽑아냈다. 하나의 프롬프트로 다 하려 하지 않고 용도별로 나눈 게 이전과 달라진 점이다.
- **파이프라인은 로컬 LLM 서버(LM Studio, OpenAI 호환 API)를 거치도록 조립했다** — 전사 → 두 갈래 요약 → 파일 저장까지 `main.py` 하나로 순서대로 실행되게 만들었다.
- **이 코드 자체는 GPT로 바이브 코딩했다** — 회의록을 자동화하는 도구를 만드는 과정도, AI와 함께 짰다.
<br>

### 기술 스택
- STT / 화자분리: WhisperX, PyTorch (GPU)
- 요약: 로컬 LLM(mistral) — LM Studio 기반 OpenAI 호환 API
- 코딩 보조: GPT (바이브 코딩)
- 언어: Python, requests
<br>

### 코드 샘플
 
전사·화자분리 (`whisperx_runner.py`)
<br>

```python
model = whisperx.load_model(MODEL_SIZE, DEVICE, compute_type="float16" if DEVICE == "cuda" else "float32")
result = model.transcribe(AUDIO_PATH)
 
diarize_model = whisperx.DiarizationPipeline(use_auth_token=HUGGINGFACE_TOKEN, device=DEVICE)
result = diarize_model(AUDIO_PATH, result)
 
for seg in result["segments"]:
    speaker = seg.get("speaker", "Unknown")
    f.write(f"[{seg['start']:.2f}s - {seg['end']:.2f}s] {speaker}: {seg['text'].strip()}\n")
```
<br>
목적별로 나눈 요약 프롬프트 (`summarize_meeting.py` / `summarize_personal.py`)
<br>

    ```python

    # 회의록용 — 11개 항목으로 정형화
    prompt = f"""
    다음 텍스트는 회의 전사입니다. 이를 정형화된 회의록 형식으로 요약해 주세요.
    1. 회의 제목: ... 6. 주요 논의 내용: ... 9. 액션 아이템: ...
    === 회의 원문 ===
    \"\"\"{transcript_text}\"\"\"
    """
    
    # 화자별 요약용 — 같은 전사본, 다른 목적
    prompt = f"""
    다음 텍스트는 화자 구분이 포함된 회의 전사입니다.
    각 화자의 발언 중 주목할 만한 발언, 중요 결정, 제안, 요청 등을 요약해 주세요.
    === 회의 원문 ===
    \"\"\"{transcript_text}\"\"\"
    """
    ```

### 결과


- 회의가 끝나면 녹음 파일 하나로 정형화된 회의록과 발언자별 요약이 동시에 나오는 구조를 만들었고, Notion에 바로 공유했다.
- 클라우드 API 대신 로컬 STT·로컬 LLM으로 구성해서, 회의 내용을 외부로 보내지 않고도 자동화가 가능하다는 걸 확인했다.
- 하나의 프롬프트로 모든 걸 해결하려 하지 않고, 목적별로 프롬프트를 쪼개는 습관이 나아졌다.
